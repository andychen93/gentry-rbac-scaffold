## 四、缺陷清单

### 4.1 缺陷汇总

| 缺陷编号 | 严重程度 | 缺陷描述 | 复现步骤 | 对应用例 | 状态 |
|----------|----------|----------|----------|----------|------|
| BUG-001 | 严重 | 分配角色API返回系统异常(code:10001)，角色未保存 | 1. 点击任意用户"角色"按钮 2. 选择角色 3. 点击确定 | TC-06 | 待修复 |
| BUG-002 | 严重 | 前端全局缺少HTTP错误响应处理：后端返回业务错误(code!=0)时，前端不显示任何提示信息 | 1. 触发任何会返回业务错误的操作（如登录失败、新增重复用户名、删除当前用户） | TC-11, TC-12, TC-13 | 待修复 |
| BUG-003 | 一般 | 分配角色弹窗提交后不自动关闭（与BUG-001/002相关） | 1. 打开分配角色弹窗 2. 选择角色 3. 点击确定，弹窗不关闭 | TC-06 | 待修复 |
| BUG-004 | 一般 | 新增用户弹窗在业务错误时不关闭 | 1. 新增重复用户名 2. 点击确定，弹窗不关闭 | TC-12 | 待修复 |

### 4.2 严重程度定义

| 等级 | 定义 |
|------|------|
| 致命 | 功能完全不可用、系统崩溃、数据丢失 |
| 严重 | 核心功能异常、流程中断但可绕过 |
| 一般 | 非核心功能异常、UI 显示错误 |
| 提示 | 文案错误、样式微调、体验优化 |

## 七、建议与风险

### 7.1 测试覆盖说明

| 覆盖类型 | 是否覆盖 | 说明 |
|----------|----------|------|
| 正常流程 | 是 | 覆盖新增、编辑、删除、状态切换、重置密码、退出登录 6 个场景 |
| 异常流程 | 是 | 覆盖登录失败、重复用户名、删除admin 3 个场景 |
| 边界条件 | 部分 | 未覆盖超长输入、特殊字符、空密码等边界场景 |
| 跨模块依赖 | 否 | 未测试与角色管理、部门管理的联动 |

### 7.2 遗留风险

| 风险项 | 影响 | 建议 |
|--------|------|------|
| 前端缺少全局HTTP错误拦截 | 用户操作失败时无感知，体验极差 | 高优先级修复：在 axios/fetch 拦截器中统一处理 code!=0 的响应 |
| 分配角色后端系统异常 | 角色分配功能完全不可用 | 排查 UserController/RoleService 的角色分配接口实现 |
| 弹窗不关闭问题 | 用户卡在弹窗中无法继续操作 | 在API错误时也应关闭弹窗或给出明确提示 |

### 7.3 改进建议

| 建议 | 优先级 | 说明 |
|------|--------|------|
| 前端统一错误处理拦截器 | 高 | 在请求层统一判断 response.data.code !== 0 时弹出 message.error 提示 |
| 修复分配角色后端异常 | 高 | 排查 PUT /api/v1/users/{id}/roles 接口的 10001 系统异常原因 |
| 弹窗提交失败时自动关闭 | 中 | 表单提交API返回业务错误时也应关闭弹窗，避免用户卡住 |
| 补充边界条件测试 | 中 | 增加超长用户名、特殊字符密码、空必填项等边界场景 |
| 前端表单校验增强 | 低 | 新增用户时在前端增加用户名重复校验，减少无效API调用 |
