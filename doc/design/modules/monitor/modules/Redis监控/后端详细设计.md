# 一、数据库设计

> ⚠️ 本模块不创建业务表。Redis 监控数据全部来自 `Redis INFO` 命令和 `SCAN` 遍历，无需持久化。

## 1.1 表清单与业务职责

无业务表。Redis 监控是纯读操作，数据源为 Redis Server 运行时信息。

# 二、模块目标与边界

**模块解决的业务问题：**
为运维和管理员提供 Redis 实例的实时运行状态监控，包括：服务信息、内存使用、连接数、命令统计、Key 管理等。方便排查性能瓶颈和 Key 泄漏。

**模块不解决的问题：**
- 不做 Redis 集群管理（Sentinel/Cluster 拓扑）
- 不做历史数据趋势分析（后续可接入 Prometheus + Grafana）
- 不做 Redis 配置修改（只读监控）
- 不做慢查询日志分析

**是否核心链路：** 否（运维辅助功能）

## 4.2 Redis Key 定义信息

本模块需要维护一份 **应用级 Key 定义清单**，用于告诉前端本系统使用了哪些 Redis Key 模式：

| Key 模式 | 类型 | 用途 | TTL | 管理方 |
|----------|------|------|-----|--------|
| `Authorization:login:token:{tokenValue}` | String | Token → LoginId 映射 | 30min（可配置） | Sa-Token 自动 |
| `Authorization:login:session:{loginId}` | Hash | 用户 Session | 30min（可配置） | Sa-Token 自动 |
| `blacklist:{tokenValue}` | String | JWT 黑名单 | Token 剩余有效期 | TokenBlacklistService |
| `Authorization:timeout:{tokenValue}` | String | Token 过期时间辅助 | 与 Token 同步 | Sa-Token 自动 |

> 注：Key 前缀来源于 `sa-token.token-name` 配置（当前 `Authorization`），修改配置时需同步更新 `RedisKeyDefines`。

# 五、行为流程与用例设计

## 5.1 主流程（时序图）

### 5.1.1 获取 Redis 监控信息

```mermaid
sequenceDiagram
    participant FE as 前端监控页面
    participant Ctrl as RedisMonitorController
    participant Svc as RedisMonitorService
    participant Redis as Redis Server

    FE->>Ctrl: GET /api/v1/monitor/redis/info
    Ctrl->>Svc: getMonitorInfo()
    Svc->>Redis: INFO all
    Redis-->>Svc: 原始 INFO 文本
    Svc->>Svc: 解析 INFO 为 RedisInfoVO
    Svc->>Redis: INFO commandstats
    Redis-->>Svc: 命令统计文本
    Svc->>Svc: 解析为 List<RedisCommandStatVO>
    Svc->>Redis: DBSIZE
    Redis-->>Svc: key 总数
    Svc->>Svc: 组装 RedisMonitorVO
    Svc-->>Ctrl: RedisMonitorVO
    Ctrl-->>FE: R<RedisMonitorVO>
```

### 5.1.2 Key 列表查询（SCAN）

```mermaid
sequenceDiagram
    participant FE as 前端监控页面
    participant Ctrl as RedisMonitorController
    participant Svc as RedisKeyService
    participant Redis as Redis Server

    FE->>Ctrl: GET /api/v1/monitor/redis/keys?pattern=blacklist:*
    Ctrl->>Svc: scanKeys(pattern, pageSize)
    loop SCAN 游标遍历
        Svc->>Redis: SCAN cursor MATCH pattern COUNT 100
        Redis-->>Svc: cursor + keys[]
    end
    Svc->>Svc: 截取 pageSize 条
    loop 每个 Key 获取类型和 TTL
        Svc->>Redis: TYPE key
        Redis-->>Svc: string/hash/list/set/zset
        Svc->>Redis: TTL key
        Redis-->>Svc: 剩余秒数
    end
    Svc-->>Ctrl: List<RedisKeyVO>
    Ctrl-->>FE: R<PageResult<RedisKeyVO>>
```

### 5.1.3 获取 Key Value

```mermaid
sequenceDiagram
    participant FE as 前端监控页面
    participant Ctrl as RedisMonitorController
    participant Svc as RedisKeyService
    participant Redis as Redis Server

    FE->>Ctrl: GET /api/v1/monitor/redis/keys/{key}/value
    Ctrl->>Svc: getKeyValue(key)
    Svc->>Redis: TYPE key
    Redis-->>Svc: 数据类型
    alt 类型为 string
        Svc->>Redis: GET key
    else 类型为 hash
        Svc->>Redis: HGETALL key
    else 类型为 list
        Svc->>Redis: LRANGE key 0 -1
    else 类型为 set
        Svc->>Redis: SMEMBERS key
    else 类型为 zset
        Svc->>Redis: ZRANGE key 0 -1 WITHSCORES
    end
    Redis-->>Svc: value
    Svc->>Svc: 格式化 value 为 JSON 字符串
    Svc-->>Ctrl: RedisKeyVO
    Ctrl-->>FE: R<RedisKeyVO>
```

## 5.2 关键业务规则说明

- **前置条件**：Redis 连接正常（`StringRedisTemplate` 可用）
- **核心校验**：
  - Key 查询时 pattern 不允许为空，防止全量扫描
  - Key 删除需二次确认（前端弹窗）
  - 只读操作，不修改 Redis 配置
- **失败路径**：
  - Redis 连接失败 → 全局异常处理返回 500 + 错误信息
  - Key 不存在 → 返回 404
  - 权限不足 → 返回 403

**响应示例：**

```json

  "message": "success",
```

**说明：**
- 慢日志阈值由 Redis 自身控制：`CONFIG SET slowlog-log-slower-than <us>`

- 结果按 `durationMicros` 降序排列

## 6.8 API-007：清空慢查询日志（v1.1 新增）

### 入参设计

无请求参数。

### 出参设计

无 data，仅返回操作结果。

```json
{ "code": 0, "message": "success" }
```

**说明：**
- 执行 Redis `SLOWLOG RESET`，清空整个 Redis 实例的慢日志历史
- 该操作不可恢复，仅 `monitor:redis:slowlog:reset` 权限（默认仅 SUPER_ADMIN）可调用
- 前端需二次确认

| API-006 | `monitor:redis:info` | 获取慢日志 | 否 |
| API-007 | `monitor:redis:slowlog:reset` | 清空慢日志 | 仅 SUPER_ADMIN |

## 7.2 安全检查清单

- [x] 所有接口配置了 Sa-Token 认证
- [x] Key 查询 pattern 防止全量扫描（`*` 单独使用时限制返回数量）
- [x] Key 删除操作有权限控制和操作日志
- [x] Key Value 展示截断（最大 500 字符），防止大 Value 导致 OOM
- [x] 无 SQL 注入风险（不涉及数据库）
- [x] 无 XSS 风险（后端只返回 JSON）
