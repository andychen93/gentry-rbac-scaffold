# 邮箱注册与找回 — 后端详细设计

| 项目 | 内容 |
|------|------|
| 微服务/应用 | gentry-rbac-spring-boot-starter（平台能力下沉） |
| 功能 | 邮箱自助注册、邮箱验证、邮箱登录、找回密码 |
| 需求来源 | budget 基线 v1.2 §2（首版仅邮箱注册/登录，须邮箱验证，手机号延期） |
| 消费方 | precision/budget（首个消费者）；gentry-start 狗粮不启用注册端点 |
| 日期 | 2026-09-01 |

## 1. 背景与边界

- 现状：`AuthController` 仅 login/logout/user-info/password/profile。`UserCreateDTO.username`
  正则 `^[a-zA-Z][a-zA-Z0-9_]{3,19}$` 拒绝邮箱格式；登录按 `(tenant_id, username)` 查询。
- 本设计把「自助注册 + 邮箱验证 + 找回密码」作为**平台能力**下沉 rbac starter，
  消费项目（budget）不再自建认证端点。
- **不动的东西**：`sys_user` 表结构不加列（验证状态放新表）；username 正则不放宽
  （注册用户 username 由平台生成合规名）；`sys_menu`/`sys_role` 语义不变。

## 2. 数据库设计

### 2.1 新表 `sys_email_token`（common 段 V16）

一次性令牌：注册验证与密码找回共用一张表，靠 `purpose` 区分。

| 字段 | 类型 | 约束/说明 |
|------|------|-----------|
| id | BIGINT | 主键，flexId |
| tenant_id | BIGINT | NOT NULL，租户隔离 |
| email | VARCHAR(255) | NOT NULL，目标邮箱（小写规范化后存） |
| purpose | VARCHAR(20) | NOT NULL，`REGISTER` / `RESET_PASSWORD` |
| token_hash | CHAR(64) | NOT NULL，令牌 SHA-256；**不存明文** |
| user_id | BIGINT | NULL；REGISTER 在验证时回填创建的用户 |
| expires_at | TIMESTAMP | NOT NULL；REGISTER 48h / RESET 30min |
| used_at | TIMESTAMP | NULL；一次性，用后回填 |
| create_by/create_time/update_by/update_time/deleted | — | 对齐 TenantEntity |

索引：`uk_token_hash (token_hash)`（查令牌唯一入口）；`idx_email_purpose (tenant_id, email, purpose)`（重发前查最近一条）。

> 三库（MySQL/PG/SQLite）均为普通 `CREATE TABLE` + 索引，无方言差异，放 `common/V16__create_email_token.sql`。

### 2.2 `sys_user` 不加列

邮箱是否已验证由 `sys_email_token`（purpose=REGISTER 且 used_at 非空）表达；
登录侧「未验证邮箱拒绝登录」通过查该表判断。避免动平台表结构。

## 3. 邮件模块（新包 `com.gentry.rbac.mail`）

对齐 SMS 网关模式（`SmsGateway` + `LoggingSmsGateway` + `NotificationConfig`）：

```java
public interface MailGateway {
    void send(String to, String subject, String htmlBody);
}

@Component @ConditionalOnProperty("gentry.mail.enabled")
public class SmtpMailGateway implements MailGateway { /* JavaMailSender */ }

@Bean @ConditionalOnMissingBean(MailGateway.class)
public MailGateway loggingMailGateway() { /* 日志桩，开发默认 */ }
```

- 依赖：`spring-boot-starter-mail`（gentry-rbac-starter pom 新增；版本由 spring-boot-parent 管）。
- 配置（`GentryMailProperties`，前缀 `gentry.mail`）：
  - `enabled`（默认 false → 用日志桩）
  - `from`（发件人地址，必填 when enabled）
  - `verify-url-base` / `reset-url-base`（消费方前端拼链接的基址，如 `https://budget.example.com`）
  - `register-token-ttl-hours`（默认 48）/ `reset-token-ttl-minutes`（默认 30）
  - `resend-cooldown-minutes`（默认 1，防刷）
- SMTP 参数直接复用 Spring 标准的 `spring.mail.host/port/username/password`，不另造一套。
- **@ConditionalOnMissingBean**：消费方需要自定义邮件通道（如企业邮件 API）时提供自己的 `MailGateway` Bean 即覆盖。
- 开发环境对接 Mailpit：`spring.mail.host=localhost:1025`，budget 的 docker-compose 补服务。

## 4. API 设计

新增端点全部挂在 `AuthController`（`/api/v1/auth/*`），**公开端点**（加入 Sa-Token 放行清单的方式由消费方 exclude 配置继续承担，rbac 不新增白名单机制；见 §7 集成）。

| # | 方法 | 路径 | 说明 |
|---|------|------|------|
| AUTH-007 | POST | `/api/v1/auth/register` | 邮箱+密码+昵称注册；发验证邮件；不登录 |
| AUTH-008 | POST | `/api/v1/auth/verify-email` | `{ token }`；验证通过即注册完成（建用户） |
| AUTH-009 | POST | `/api/v1/auth/resend-verification` | `{ email }`；冷却期内 409 |
| AUTH-010 | POST | `/api/v1/auth/password/forgot` | `{ email }`；发重置邮件（不泄露邮箱是否存在） |
| AUTH-011 | POST | `/api/v1/auth/password/reset` | `{ token, newPassword }`；重置并踢下线 |
| AUTH-012 | POST | `/api/v1/auth/login` | **增强**：`username` 字段兼容邮箱登录（见 §5） |

### 4.1 AUTH-007 register

请求 `RegisterDTO`：`email`（@Email，必填）、`password`（复用 UserCreateDTO 的强度正则）、`nickname`（2-20）。

流程：
1. 规范化 email（trim + 小写）。
2. 查 `(tenant_id, email)` 已有已验证用户 → `EMAIL_ALREADY_EXISTS`（20040）。
   （`sys_user` 邮箱无唯一键，靠查询判断；并发窗口由 verify 时再查一次兜底。）
3. 同邮箱存在未过期未使用 REGISTER 令牌且在冷却期内 → `EMAIL_RESEND_COOLDOWN`（20041）。
4. 生成 32 字节随机 token（Base64URL）；存 SHA-256；过期 48h。
5. 发邮件（含 `verify-url-base + /verify-email?token=…`）；**邮件失败不回滚令牌**，可走 resend。
6. 返回 `R<Void>`（不泄露内部状态）。
7. `@RateLimit(IP, 5/min)` + `@RepeatSubmit(3s)`。

### 4.2 AUTH-008 verify-email

1. 查 `token_hash` → 无 / 过期 / 已用 → `EMAIL_TOKEN_INVALID`（20042）。
2. purpose 必须 REGISTER；再查邮箱冲突（并发兜底）。
3. 创建用户：username = `"u" + flexId`（满足平台正则，全局不冲突）；
   email 存规范化值；nickname 取令牌上的；密码取注册时（注册时暂存于令牌表 `credential` 字段？
   ——**否**：密码 BCrypt 哈希存 `sys_email_token.payload` 列，VARCHAR(200)，见 §2.1 补充）。
4. 回填令牌 `used_at`、`user_id`。
5. **默认角色绑定**：消费方配置 `gentry.register.default-role-code`（如 budget 的
   `BUDGET_USER`）时，按 `(tenant_id, role_code)` 查角色并写 `sys_user_role`；
   角色不存在或写失败仅记日志，不阻断注册。
6. 返回 `R<Void>`；前端引导登录。

> 设计取舍：注册时密码哈希须暂存到验证完成。`sys_email_token` 增加 `payload VARCHAR(200) NULL` 列
> 存 BCrypt 哈希与 nickname（JSON）。令牌一次性且用后置 deleted=1，残留风险可接受。
>
> 匿名端点租户上下文：注册/验证/找回均在未登录状态调用，`UserContext.getTenantId()`
> 为 null，服务内部统一回落 `TenantConstants.DEFAULT_TENANT_ID`（首版单默认租户）。

### 4.3 AUTH-010/011 找回密码

- forgot：不论邮箱是否存在都返回 `R.ok()`（防枚举）；存在已验证用户才真正发信。
- reset：校验令牌（purpose=RESET_PASSWORD）→ 更新密码 + `pwd_update_time` →
  `TokenBlacklistService` 踢该用户全部在线 token（复用强制下线机制）→ 令牌置 used。
- 重置后旧密码失效；登录失败计数器清零。

## 5. 登录增强（邮箱登录）

`AuthServiceImpl.findAndValidateUser`：`username` 含 `@` 时先按邮箱查：

```sql
SELECT * FROM sys_user WHERE tenant_id=? AND email=? AND deleted=0 LIMIT 1
```

- 命中且邮箱已验证（存在 purpose=REGISTER 且 used_at 非空的令牌）→ 正常校验密码。
- 未验证 → `EMAIL_NOT_VERIFIED`（20043）。
- `UserMapper` 补 `selectByEmail(tenantId, email)`。
- 用户名登录路径完全不变（管理端账号无邮箱也照旧）。

## 6. 错误码（gentry-core ErrorCode 追加）

| 码 | 枚举 | 文案 |
|----|------|------|
| 20040 | EMAIL_ALREADY_EXISTS | 邮箱已被注册 |
| 20041 | EMAIL_RESEND_COOLDOWN | 发送过于频繁，请稍后再试 |
| 20042 | EMAIL_TOKEN_INVALID | 链接无效或已过期 |
| 20043 | EMAIL_NOT_VERIFIED | 邮箱尚未验证，请先查收验证邮件 |

i18n：`error.properties` / `error_zh_CN.properties` / `error_en_US.properties` 各补 4 条 key
（`error.auth.email.*`）。段落沿用「认证 20018-20021」之后的空号段 20040-20043。

## 7. 消费方（budget）集成方式

1. `mvn install` 刷新本地 SNAPSHOT，budget 引新版本。
2. budget `application.yml`：
   ```yaml
   gentry:
     mail:
       enabled: true            # 开发对接 Mailpit
       from: no-reply@budget.local
       verify-url-base: http://localhost:5173
       reset-url-base: http://localhost:5173
   spring:
     mail:
       host: localhost
       port: 1025               # Mailpit
   ```
3. 匿名放行：`gentry-core` 的 `SaTokenConfig.excludePathPatterns` 已登记
   `/api/v1/auth/register|verify-email|resend-verification|password/forgot|password/reset`
   （登录拦截器清单是平台级硬编码，注册/验证属平台匿名语义，随 starter 分发；防刷靠端点注解）。
4. budget 侧**删除**自建 `/api/v1/auth/*` 的计划（API 清单 v1.2 §2 前四行即本设计端点）。

## 8. 权限与安全

- 注册/验证/找回端点全部 `@RateLimit(IP)` + `@RepeatSubmit`。
- 令牌：32 字节 SecureRandom、Base64URL、只存 hash、一次性、短 TTL、用后即焚。
- 防枚举：forgot 统一 200；register 的 EMAIL_ALREADY_EXISTS 仅在「对方主动注册同一邮箱」场景暴露，
  属可接受语义（主流做法一致）。
- 邮件内容 HTML 模板内置（验证/重置两套），标题走 i18n（`mail.subject.verify` / `mail.subject.reset`，
  复用现有 messages basename，新增 `mail` 段 key）。

## 9. 测试设计（JUnit5 + Mockito，不启动 Spring，对齐 CaptchaServiceImplTest 风格）

| 用例 | 断言 |
|------|------|
| register_邮箱已存在 | EMAIL_ALREADY_EXISTS |
| register_冷却期内重发 | EMAIL_RESEND_COOLDOWN |
| register_正常 | 令牌落库（hash 非 token）、MailGateway.send 被调 1 次 |
| verify_令牌无效/过期/已用 | EMAIL_TOKEN_INVALID |
| verify_正常 | sys_user 建立（username=u+id）、令牌 used_at 回填 |
| forgot_邮箱不存在 | 仍 R.ok，send 不被调 |
| reset_正常 | 密码更新、黑名单踢下线、令牌置 used |
| login_邮箱登录_未验证 | EMAIL_NOT_VERIFIED |
| login_邮箱登录_正常 | 走 selectByEmail 命中 |
