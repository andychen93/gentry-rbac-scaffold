# 一、设计目标（What & Why）

## 是什么（What）

自动填充处理器是数据库操作的公共字段自动赋值机制。基于 MyBatis-Flex 的 `InsertListener` + `UpdateListener`（实体拦截器）接口，在 INSERT 和 UPDATE 操作执行前，自动填充 `tenant_id`、`create_time`、`create_by`、`update_time`、`update_by`、`deleted` 等公共字段，确保所有数据记录的审计字段完整、一致，开发人员无需手动设置这些字段。

核心职责：

1. **INSERT 填充**：新增记录时自动填充租户ID、创建时间、创建人、更新时间、更新人、删除标记
2. **UPDATE 填充**：更新记录时自动刷新更新时间、更新人
3. **租户ID 注入**：与多租户拦截器配合，确保写入数据携带正确的 `tenant_id`
4. **审计追溯**：通过 `create_by` / `update_by` 记录数据操作人，支持审计追踪
5. **逻辑删除保护**：确保新记录的 `deleted` 字段默认为 0（未删除）

## 为什么（Why）

1. **数据完整性**：所有业务表都包含 `tenant_id`、`create_time`、`update_time` 等必填字段，手动设置容易遗漏且重复代码量大
2. **一致性保障**：集中式填充确保所有模块的时间字段取值一致（统一 `LocalDateTime.now()`），操作人字段取值一致（统一从 `UserContext` 获取）
3. **开发效率**：开发人员只需关注业务字段，公共字段由框架自动处理。一个新增操作至少节省 5 行 set 代码
4. **审计合规**：通过 `create_by` / `update_by` 字段，可追溯任意数据的创建者和最后修改者
5. **架构原则**：CLAUDE.md 第七章 7.1 明确定义了实体的 `@TableField(fill = FieldFill.INSERT)` 等填充策略

# 二、定位与上下文（Where & When）

## 在哪里（Where）

位于 `precision-core` 模块的 `com.precision.core.interceptor` 包中，作为 MyBatis-Flex 的实体拦截器，在 Mapper 层执行 SQL 之前触发。

在系统架构中的位置：

```
Controller → Service → Mapper
                        ↓ 调用 insert/update
                   [AutoFillHandler]
                   自动填充公共字段
                        ↓
                   SQL 执行 → Database
```

依赖关系：

- **被依赖方**：所有包含数据库写入的业务模块均依赖此处理器自动填充公共字段
- **依赖方**：
  - MyBatis-Flex `InsertListener` + `UpdateListener`（框架提供的实体拦截接口）
  - `UserContext`（`com.precision.core.security.UserContext`）—— 获取当前用户ID和租户ID
  - 实体类注解 `@TableField(fill = FieldFill.INSERT)` / `@TableField(fill = FieldFill.INSERT_UPDATE)`

## 在何时（When）

触发场景：

| 触发场景 | SQL 操作 | 填充字段 |
|----------|----------|----------|
| 新增业务数据 | INSERT | tenant_id, create_time, create_by, update_time, update_by, deleted |
| 修改业务数据 | UPDATE | update_time, update_by |
| 系统级新增 | INSERT | create_time, update_time, deleted（无 tenant_id、无 create_by） |
| 设备数据上报（无用户上下文） | INSERT | tenant_id（从设备上下文获取）, create_time, update_time |

特殊场景说明：

- **登录/注册接口**：无用户上下文，`create_by` 和 `update_by` 不填充或设为 0
- **设备上报数据**：无登录用户，`tenant_id` 从设备信息中获取，`create_by` 设为系统默认值
- **定时任务**：无登录用户，`create_by` 设为 -1（系统任务标识）

# 四、实现思路（How）

## 核心技术方案

基于 MyBatis-Flex 的 `InsertListener` + `UpdateListener` 接口，实现 `onInsert` 和 `onUpdate` 方法。

### 4.1 字段填充规则

| 字段 | INSERT | UPDATE | 取值来源 | 类型 |
|------|--------|--------|----------|------|
| `tenant_id` | 是 | 否 | `UserContext.getTenantId()` | Long |
| `create_time` | 是 | 否 | `LocalDateTime.now()` | LocalDateTime |
| `create_by` | 是 | 否 | `UserContext.getUserId()` | Long |
| `update_time` | 是 | 是 | `LocalDateTime.now()` | LocalDateTime |
| `update_by` | 是 | 是 | `UserContext.getUserId()` | Long |
| `deleted` | 是 | 否 | `0`（未删除） | Integer |

### 4.2 实体类配合方式

实体类通过 MyBatis-Flex 的 `@TableField` 注解声明字段填充策略：

```java
@Data
@TableName("biz_vehicle")
public class Vehicle {
    @TableId(type = IdType.Generator, value = KeyGenerators.FlexID.class)
    private Long id;

    @Column(tenantId = true)
    private Long tenantId;

    private String plateNumber;

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT)
    private Long createBy;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private Long updateBy;

    @TableLogic
    private Integer deleted;
}
```

### 4.3 AutoFillHandler 实现

核心逻辑流程：

```
onInsert(entity):
  1. instanceof 检查 entity 是否为 TenantEntity
     → 是且 tenantId 为 null：从 UserContext 获取并填充
  2. instanceof 检查 entity 是否为 BaseEntity
     → 是且 createTime 为 null：填充 LocalDateTime.now()
  3. instanceof 检查 entity 是否为 BaseEntity
     → 是且 createBy 为 null：从 UserContext 获取 userId
     → 无用户上下文：设为 null（系统操作）
  4. instanceof 检查 entity 是否为 BaseEntity
     → 是且 updateTime 为 null：填充 LocalDateTime.now()
  5. instanceof 检查 entity 是否为 BaseEntity
     → 是且 updateBy 为 null：从 UserContext 获取 userId
  6. instanceof 检查 entity 是否为 BaseEntity
     → 是且 deleted 为 null：设为 0

onUpdate(entity):
  1. instanceof 检查 entity 是否为 BaseEntity
     → 强制填充 LocalDateTime.now()（覆盖原值）
  2. instanceof 检查 entity 是否为 BaseEntity
     → 强制填充 UserContext.getUserId()
```

### 4.4 无用户上下文处理

| 场景 | tenant_id | create_by | update_by |
|------|-----------|-----------|-----------|
| 正常请求（已登录） | UserContext.getTenantId() | UserContext.getUserId() | UserContext.getUserId() |
| 登录/注册接口 | 不填充 | 0 | 0 |
| 设备上报（无登录） | 从设备上下文获取 | -2（设备上报标识） | -2 |
| 定时任务 | 不填充 | -1（系统任务标识） | -1 |

### 4.5 注册拦截器

通过 MyBatis-Flex 的配置方式注册：

```java
@Configuration
public class MyBatisFlexConfig {
    @Bean
    public AutoFillHandler autoFillHandler() {
        return new AutoFillHandler();
    }

    @Bean
    public MybatisFlexCustomizer mybatisFlexAutoFillCustomizer(AutoFillHandler autoFillHandler) {
        return options -> {
            // 通过 registerInsertListener / registerUpdateListener 注册
            options.registerInsertListener(autoFillHandler);
            options.registerUpdateListener(autoFillHandler);
        };
    }
}
```

## 关键类和接口设计

| 类名 | 包路径 | 职责 |
|------|--------|------|
| `AutoFillHandler` | `com.precision.core.interceptor` | 实现 InsertListener + UpdateListener，自动填充公共字段 |
| `MyBatisFlexConfig` | `com.precision.core.config` | 注册拦截器和全局配置 |
| `UserContext` | `com.precision.core.security` | 提供当前用户ID和租户ID |

# 五、预期效果与验收标准

## 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 字段填充耗时 | < 0.5ms | instanceof 类型检查 + 字段赋值 |
| 性能优化 | 直接类型转换 | 避免反射调用，编译期类型安全 |
| 并发安全 | 无状态 | LocalDateTime.now() 和 UserContext 均线程安全 |

## 功能验收标准

| 编号 | 验收项 | 验证方式 |
|------|--------|----------|
| F-001 | INSERT 自动填充 tenant_id | 新增数据后查询，确认 tenant_id 正确 |
| F-002 | INSERT 自动填充 create_time | 确认 create_time 与当前时间一致 |
| F-003 | INSERT 自动填充 create_by | 确认 create_by 为当前登录用户ID |
| F-004 | INSERT 自动填充 update_time | 确认 update_time 与当前时间一致 |
| F-005 | INSERT 自动填充 update_by | 确认 update_by 为当前登录用户ID |
| F-006 | INSERT 自动填充 deleted = 0 | 确认 deleted 字段值为 0 |
| F-007 | UPDATE 自动刷新 update_time | 修改数据后确认 update_time 已更新 |
| F-008 | UPDATE 自动刷新 update_by | 修改数据后确认 update_by 为当前用户 |
| F-009 | 无用户上下文时不报错 | 登录接口创建用户记录时正常执行 |
| F-010 | 已有值字段不被覆盖 | 手动设置 create_time 后不被覆盖 |
| F-011 | UPDATE 不修改 create_time | 更新操作后 create_time 保持不变 |
| F-012 | 多线程并发填充正确 | 模拟并发请求，确认各线程填充各自的用户ID |
