# 一、设计目标（What & Why）

## 是什么（What）

全局异常处理是平台级别的统一错误捕获与响应机制。基于 Spring Boot 的 `@RestControllerAdvice` 机制，在 Controller 层之外拦截所有未处理的异常，将其转换为标准化的 `R<>` 统一响应格式，确保客户端始终收到结构一致、信息明确的错误响应。

核心职责：

1. **异常拦截**：捕获 Controller 层抛出的所有异常，避免异常直接暴露给客户端
2. **分类处理**：根据异常类型映射到对应的错误码和错误信息
3. **统一格式**：所有错误响应遵循 `R<>` 统一格式，包含 `code`、`message`、`traceId`
4. **日志记录**：异常发生时记录完整的错误日志，包含 traceId 便于排查
5. **安全防护**：生产环境隐藏技术细节（如 SQL 语句、堆栈信息），防止信息泄露

## 为什么（Why）

1. **一致性保障**：没有全局异常处理时，不同开发人员可能返回不同的错误格式（有的返回 JSON，有的返回 HTML 错误页），前端无法统一解析
2. **降低开发成本**：业务代码无需在每个方法中编写 try-catch，专注于业务逻辑即可
3. **安全合规**：未处理的异常可能暴露数据库结构、SQL 语句、内部类路径等敏感信息
4. **运维效率**：通过 traceId 关联日志与错误响应，快速定位线上问题
5. **框架集成**：Sa-Token、MyBatis-Flex、Spring Validation 等框架各自抛出不同类型的异常，需要统一收口处理

# 二、定位与上下文（Where & When）

## 在哪里（Where）

位于 `precision-core` 模块的 `com.precision.core.exception` 包中，作为所有 Controller 外围的"AOP 拦截层"。

在系统架构中的位置：

```
请求进入 → Filter 链 → DispatcherServlet → Controller → Service → Mapper
                                                           ↓ 抛出异常
                   GlobalExceptionHandler ← @RestControllerAdvice 拦截
                           ↓
                   封装为 R<> 统一响应 → 返回客户端
```

依赖关系：

- **被依赖方**：所有模块（precision-gateway、precision-business、precision-protocol）均依赖 precision-core，因此全局异常处理对全平台生效
- **依赖方**：
  - `R<>` 统一响应类（`com.precision.core.common.R`）
  - `ErrorCode` 枚举（`com.precision.core.common.ErrorCode`）
  - `BizException` 业务异常（`com.precision.core.exception.BizException`）
  - `UserContext` 上下文（`com.precision.core.security.UserContext`）—— 获取 traceId

## 在何时（When）

触发场景：

| 触发场景 | 异常类型 | 典型案例 |
|----------|----------|----------|
| 参数校验失败 | `MethodArgumentNotValidException` | @Valid 注解校验不通过 |
| 参数类型不匹配 | `MethodArgumentTypeMismatchException` | 路径参数应为 Long 但传入字符串 |
| 请求体不可读 | `HttpMessageNotReadableException` | JSON 格式错误、缺少请求体 |
| 业务规则违反 | `BizException` | 车牌号重复、设备不存在 |
| 未登录访问 | `NotLoginException` | Token 过期或未携带 |
| 权限不足 | `NotRoleException` / `NotPermissionException` | 无角色或无权限 |
| 数据库唯一约束冲突 | `DuplicateKeyException` | 插入重复主键/唯一键 |
| 其他未知异常 | `Exception` | NPE、网络超时等 |

# 三、主要用户与交互方（Who）

## 面向谁（Who）

| 角色 | 关注点 |
|------|--------|
| **前端开发** | 依赖统一的 `R<>` 响应格式处理错误提示，通过 `code` 判断错误类型，通过 `message` 展示错误信息 |
| **后端开发** | 业务代码直接 `throw new BizException(ErrorCode.XXX)` 即可，无需关心异常如何被捕获和格式化 |
| **测试人员** | 通过标准化的错误码验证接口的异常场景覆盖 |
| **运维人员** | 通过 traceId 在日志系统中快速定位问题 |
| **API 调用方** | 第三方系统集成时依赖一致的错误响应格式进行错误处理 |

## 与其他组件的交互

| 交互组件 | 交互方式 | 说明 |
|----------|----------|------|
| `R<>` | 创建实例 | 异常处理器将错误信息封装为 `R<>` 返回 |
| `ErrorCode` | 读取错误码 | 业务异常携带 ErrorCode，处理器提取 code 和 message |
| `BizException` | 捕获处理 | 业务代码主动抛出的业务异常 |
| `UserContext` | 读取 traceId | 将 traceId 写入响应，便于问题追踪 |
| Sa-Token | 捕获认证异常 | NotLoginException、NotRoleException、NotPermissionException |
| MyBatis-Flex | 捕获数据异常 | DuplicateKeyException 等数据库异常 |
| Spring Validation | 捕获校验异常 | MethodArgumentNotValidException |

# 四、实现思路（How）

## 核心技术方案

基于 Spring Boot 3.2 的 `@RestControllerAdvice` + `@ExceptionHandler` 注解实现，无需额外依赖。

### 4.1 ErrorCode 扩展设计

在现有 `ErrorCode` 枚举基础上，按模块范围扩展错误码：

```java
@Getter
@AllArgsConstructor
public enum ErrorCode {

    // ========== 系统错误 10001-10099 ==========
    SYSTEM_ERROR(10001, "系统异常，请稍后重试"),
    PARAM_ERROR(10002, "参数校验失败"),
    METHOD_NOT_ALLOWED(10003, "请求方法不允许"),
    PARAM_TYPE_MISMATCH(10004, "请求参数类型不匹配"),
    HTTP_MESSAGE_NOT_READABLE(10005, "HTTP消息不可读"),

    // ========== RBAC 业务错误 20001-20099 ==========
    // （已有 RBAC 业务错误码保持不变）

    // ========== 认证/数据错误 30001-30099 ==========
    TOKEN_INVALID(30001, "Token无效"),
    TOKEN_EXPIRED(30002, "Token已过期"),
    PERMISSION_DENIED(30003, "权限不足"),
    DATA_EXISTS(30010, "数据已存在"),
    DATA_NOT_FOUND(30011, "数据不存在"),

    // ========== 安全控制 40001-40099 ==========
    TOO_MANY_REQUESTS(40001, "请求过于频繁"),
    DUPLICATE_SUBMIT(40002, "重复提交"),

    // ========== 设备错误 50001-50099（预留） ==========

    private final int code;
    private final String message;
}
```

### 4.2 GlobalExceptionHandler 设计

```java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {
```

**异常处理方法清单：**

| 方法 | 异常类型 | 错误码 | 日志级别 |
|------|----------|--------|----------|
| `handleBizException` | `BizException` | 异常自带 code | WARN |
| `handleNotLogin` | `NotLoginException` | 30001/30002 | WARN |
| `handleNotRole` | `NotRoleException` | 30003 | WARN |
| `handleNotPermission` | `NotPermissionException` | 30003 | WARN |
| `handleValidation` | `MethodArgumentNotValidException` | 10002 | WARN |
| `handleTypeMismatch` | `MethodArgumentTypeMismatchException` | 10004 | WARN |
| `handleNotReadable` | `HttpMessageNotReadableException` | 10005 | WARN |
| `handleDuplicateKey` | `DuplicateKeyException` | 30010 | ERROR |
| `handleException` | `Exception` | 10001 | ERROR |

### 4.3 BizException 设计

```java
@Getter
public class BizException extends RuntimeException {
    private final int code;
    private final String message;

    public BizException(ErrorCode errorCode) { ... }
    public BizException(ErrorCode errorCode, String detail) { ... }
    public BizException(int code, String message) { ... }
}
```

### 4.4 响应封装逻辑

每个异常处理方法遵循统一流程：

```
捕获异常
  → 获取 traceId（从 MDC 或 UserContext）
  → 记录日志（不同异常级别不同）
  → 构造 R.fail(code, message, traceId)
  → 返回 ResponseEntity 或直接返回 R<>
```

对于 `MethodArgumentNotValidException`，需要提取所有校验失败的字段信息，拼接为可读的错误提示：

```
"参数校验失败：车牌号不能为空; 手机号格式不正确"
```

### 4.5 AsyncUncaughtExceptionHandler

异步方法（`@Async`）中的未捕获异常不会被 `@RestControllerAdvice` 拦截，需要单独配置：

```java
@Configuration
public class AsyncConfig implements AsyncConfigurer {
    @Override
    public AsyncUncaughtExceptionHandler getAsyncUncaughtExceptionHandler() {
        return (ex, method, params) -> {
            log.error("异步方法异常 - method={}, traceId={}", method.getName(),
                MDC.get("traceId"), ex);
        };
    }
}
```

# 五、预期效果与验收标准

## 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 异常处理耗时 | < 5ms | 异常拦截、日志记录、响应封装的总耗时 |
| 日志写入 | 异步 | 不阻塞请求响应 |
| 内存占用 | 可忽略 | 仅有类实例，无状态对象 |

## 功能验收标准

| 编号 | 验收项 | 验证方式 |
|------|--------|----------|
| E-001 | 业务异常返回标准 `R<>` 格式 | 抛出 BizException，验证响应包含 code、message、traceId |
| E-002 | 未登录访问返回 30001 错误码 | 不携带 Token 访问受保护接口 |
| E-003 | 权限不足返回 30003 错误码 | 普通用户访问管理员接口 |
| E-004 | 角色不足返回 30003 错误码 | 无所需角色访问接口 |
| E-005 | 参数校验失败返回字段级错误 | 提交空必填字段，验证 message 包含具体字段名 |
| E-006 | 参数类型不匹配返回 10004 | 路径参数传入非法类型 |
| E-007 | JSON 格式错误返回 10005 | 提交非法 JSON 请求体 |
| E-008 | 唯一键冲突返回 30010 | 插入重复数据 |
| E-009 | 未知异常返回通用错误信息 | 模拟 NPE，验证不暴露堆栈 |
| E-010 | 所有错误响应包含 traceId | 各类异常场景均验证 |
| E-011 | 异步方法异常被记录到日志 | @Async 方法内抛异常，验证日志输出 |
| E-012 | 生产环境不暴露技术细节 | 验证 500 错误响应不含 SQL、类路径等信息 |
