# 一、设计目标（What & Why）

## 是什么（What）

全链路追踪是为每个 HTTP 请求生成唯一追踪ID（traceId），并将 traceId 贯穿日志、响应、异步线程的分布式追踪机制。支持双模式运行：无 SkyWalking Agent 时使用 MDC（Slf4j Mapped Diagnostic Context）+ UUID 实现轻量级追踪；有 SkyWalking Agent 时自动切换为 SkyWalking 原生 traceId，实现完整的分布式链路追踪。

核心职责：

1. **TraceId 生成**：每个 HTTP 请求进入时生成唯一的 traceId（UUID 或 SkyWalking traceId）
2. **MDC 注入**：将 traceId 注入 SLF4J MDC，所有日志自动携带 traceId
3. **响应传递**：将 traceId 写入统一响应 `R<>` 的 traceId 字段，前端可展示或上报
4. **异步线程传递**：通过 `TaskDecorator` 将 traceId 传递到 `@Async` 异步线程
5. **SkyWalking 集成**：当检测到 SkyWalking Agent 时，使用 SkyWalking 的 traceId

## 为什么（Why）

1. **问题定位效率**：线上排查问题时，一个用户请求可能经过 Filter → Controller → Service → Mapper → Disruptor 多个环节。没有 traceId，需要在大量日志中根据时间范围人工关联；有了 traceId，直接 grep traceId 即可获取完整链路日志
2. **前后端协作**：前端报错时提供 traceId，后端可快速定位对应的请求日志和异常信息
3. **SkyWalking 深度集成**：CLAUDE.md 技术选型中明确选择了 SkyWalking 作为 APM 监控工具，全链路追踪是 SkyWalking 的基础能力
4. **双模式灵活性**：开发环境无需部署 SkyWalking Agent，使用 MDC 即可；生产环境部署 Agent 后自动升级为完整的分布式追踪
5. **异步场景覆盖**：位置数据上报流程中，Disruptor 异步消费、批量入库等异步操作也需要携带 traceId

# 二、定位与上下文（Where & When）

## 在哪里（Where）

位于 `precision-core` 模块的 `com.precision.core.trace` 包中，作为 Filter 链的第一个 Filter（最高优先级），确保所有后续组件都能获取到 traceId。

在请求处理链路中的位置：

```
HTTP Request
  → [TraceIdFilter]               ← 生成 traceId，注入 MDC     ← 最高优先级
  → [RequestLogFilter]            ← 记录请求日志（含 traceId）
  → [Sa-Token Filter]             ← 认证鉴权
  → DispatcherServlet
  → Controller → Service → Mapper
  → Disruptor → 异步消费
  → [TraceIdFilter]               ← 清除 MDC
  → HTTP Response（R<> 含 traceId）
```

依赖关系：

- **被依赖方**：全平台所有模块的日志输出和响应封装
- **依赖方**：
  - Servlet API（`javax.servlet.Filter`）
  - SLF4J MDC（日志上下文传递）
  - SkyWalking Toolkit（`apm-toolkit-trace`，可选）
  - `R<>` 统一响应类（携带 traceId 字段）
  - Spring `TaskDecorator`（异步线程 traceId 传递）
  - Logback（日志输出，`%X{traceId}` 模式）

## 在何时（When）

触发场景：

| 触发场景 | traceId 来源 | 说明 |
|----------|--------------|------|
| 开发环境（无 SkyWalking Agent） | UUID | `UUID.randomUUID().toString().replace("-", "")` |
| 生产环境（有 SkyWalking Agent） | SkyWalking | `TraceContext.traceId()` |
| 请求头携带 traceId | 优先使用请求头 | 支持上游服务传递 traceId |
| 异步线程 | 从父线程继承 | 通过 TaskDecorator 传递 |
| 定时任务 | UUID | 每次执行生成新 traceId |

# 四、实现思路（How）

## 核心技术方案

### 4.1 TraceIdFilter 实现

```java
@Component
@Order(Ordered.HIGHEST_PRECEDENCE)
public class TraceIdFilter implements Filter {

    private static final String TRACE_ID_HEADER = "X-Trace-Id";
    private static final String MDC_TRACE_ID = "traceId";

    @Override
    public void doFilter(ServletRequest request, ServletResponse response,
                         FilterChain chain) throws IOException, ServletException {
        try {
            // 1. 生成或获取 traceId
            String traceId = resolveTraceId((HttpServletRequest) request);

            // 2. 注入 MDC
            MDC.put(MDC_TRACE_ID, traceId);

            // 3. 设置响应头（可选）
            if (response instanceof HttpServletResponse) {
                ((HttpServletResponse) response).setHeader(TRACE_ID_HEADER, traceId);
            }

            // 4. 继续处理链
            chain.doFilter(request, response);
        } finally {
            // 5. 清除 MDC（防止线程池复用导致的 traceId 泄露）
            MDC.remove(MDC_TRACE_ID);
        }
    }
}
```

### 4.2 TraceId 生成策略（双模式）

```java
private String resolveTraceId(HttpServletRequest request) {
    // 优先级：请求头 > SkyWalking > UUID

    // 1. 从请求头获取（支持上游服务传递）
    String traceId = request.getHeader(TRACE_ID_HEADER);
    if (StringUtils.hasText(traceId)) {
        return traceId;
    }

    // 2. 尝试从 SkyWalking 获取
    try {
        traceId = TraceContext.traceId();
        if (StringUtils.hasText(traceId) && !"Ignored_Trace".equals(traceId)
            && !"N/A".equals(traceId)) {
            return traceId;
        }
    } catch (NoClassDefFoundError | Exception e) {
        // SkyWalking Agent 未安装，忽略
    }

    // 3. 生成 UUID
    return UUID.randomUUID().toString().replace("-", "");
}
```

### 4.3 R<> 响应类集成

在 `R<>` 统一响应类中，自动从 MDC 获取 traceId：

```java
@Data
public class R<T> {
    private int code;
    private String message;
    private T data;
    private String traceId;
    private long timestamp;

    public static <T> R<T> ok(T data) {
        R<T> r = new R<>();
        r.setCode(0);
        r.setMessage("success");
        r.setData(data);
        r.setTraceId(MDC.get("traceId"));          // 自动获取
        r.setTimestamp(System.currentTimeMillis());
        return r;
    }

    public static <T> R<T> fail(int code, String message) {
        R<T> r = new R<>();
        r.setCode(code);
        r.setMessage(message);
        r.setTraceId(MDC.get("traceId"));          // 自动获取
        r.setTimestamp(System.currentTimeMillis());
        return r;
    }
}
```

### 4.5 异步线程 TraceId 传递

Spring `@Async` 方法在线程池中执行，MDC 是 ThreadLocal 的，不会自动传递。通过 `TaskDecorator` 解决：

```java
public class TraceIdTaskDecorator implements TaskDecorator {
    @Override
    public Runnable decorate(Runnable runnable) {
        // 捕获父线程的 MDC 上下文
        Map<String, String> contextMap = MDC.getCopyOfContextMap();

        return () -> {
            try {
                // 在子线程中恢复 MDC 上下文
                if (contextMap != null) {
                    MDC.setContextMap(contextMap);
                }
                runnable.run();
            } finally {
                MDC.clear();
            }
        };
    }
}

@Configuration
public class AsyncConfig implements AsyncConfigurer {
    @Override
    public Executor getAsyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setTaskDecorator(new TraceIdTaskDecorator());
        // 其他线程池配置...
        return executor;
    }
}
```

### 4.6 Disruptor 线程 TraceId 传递

位置数据上报流程使用 Disruptor，其 EventHandler 在独立线程中执行。需要在事件对象中携带 traceId：

```java
// 事件对象
public class LocationEvent {
    private String traceId;       // 从生产者线程传递
    private Long tenantId;
    private LocationData data;
}

// 生产者（Netty 线程）
public void onLocation(LocationData data) {
    LocationEvent event = new LocationEvent();
    event.setTraceId(MDC.get("traceId"));  // 捕获当前线程 traceId
    event.setData(data);
    disruptor.publishEvent(event);
}

// 消费者（Disruptor 线程）
public void onEvent(LocationEvent event) {
    try {
        MDC.put("traceId", event.getTraceId());  // 恢复 traceId
        // 处理逻辑...
    } finally {
        MDC.remove("traceId");
    }
}
```

### 4.7 @Trace 注解（可选）

为关键业务方法提供显式的追踪标记，结合 SkyWalking 的 `@Trace` 注解使用：

```java
/**
 * 标记需要追踪的业务方法
 * 配合 SkyWalking，在链路中显示为独立 Span
 */
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Trace {
    /**
     * 操作名称
     */
    String operationName() default "";
}
```

使用示例：

```java
@Service
public class LocationService {

    @Trace(operationName = "批量入库位置数据")
    public void batchInsert(List<LocationData> locations) {
        // 位置数据批量入库
    }

    @Trace(operationName = "处理报警数据")
    public void processAlarm(AlarmData alarm) {
        // 报警处理逻辑
    }
}
```

# 五、预期效果与验收标准

## 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| TraceIdFilter 耗时 | < 1ms | UUID 生成 + MDC 写入 |
| MDC 读写性能 | < 0.01ms | ThreadLocal 操作 |
| 日志格式化开销 | < 0.1ms | MDC 值获取 |
| SkyWalking Agent 开销 | < 5% | 字节码增强的性能损耗（仅在 Agent 模式下） |

## 功能验收标准

| 编号 | 验收项 | 验证方式 |
|------|--------|----------|
| TR-001 | 每个请求生成唯一 traceId | 连续请求，验证每个 traceId 不同 |
| TR-002 | 日志包含 traceId | 查看日志文件，确认每条日志包含 traceId |
| TR-003 | 响应包含 traceId | 查看接口响应 JSON，确认包含 traceId 字段 |
| TR-004 | 响应头包含 traceId | 查看 HTTP 响应头 X-Trace-Id |
| TR-005 | 同一请求的日志 traceId 一致 | 发起一个请求，所有相关日志的 traceId 相同 |
| TR-006 | 不同请求的 traceId 不同 | 发起两个请求，traceId 不同 |
| TR-007 | 无 SkyWalking 时使用 UUID | 开发环境验证 traceId 为 UUID 格式 |
| TR-008 | 异步线程携带 traceId | @Async 方法内的日志包含正确的 traceId |
| TR-009 | 请求头传递 traceId | 发送带 X-Trace-Id 头的请求，使用传递的 traceId |
| TR-010 | 请求完成后 MDC 清除 | 请求完成后验证 MDC 中无 traceId（防止线程复用泄露） |
| TR-011 | 异常响应包含 traceId | 触发异常，验证错误响应包含 traceId |
| TR-012 | @Trace 注解方法在 SkyWalking 中可见 | 部署 SkyWalking 后验证链路中包含标注的方法 |
