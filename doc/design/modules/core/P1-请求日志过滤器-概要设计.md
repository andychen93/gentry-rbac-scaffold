# 一、设计目标（What & Why）

## 是什么（What）

请求日志过滤器是平台级的 HTTP 请求全链路日志记录机制。基于 Servlet `Filter` 接口实现，在请求进入时记录请求信息（方法、路径、参数、客户端IP），在请求完成时记录响应信息（状态码、耗时），为问题排查、接口审计、性能监控提供完整的请求日志数据。

核心职责：

1. **请求记录**：记录每个 HTTP 请求的方法、路径、查询参数、客户端IP、请求体（可选）
2. **响应记录**：记录响应状态码、响应耗时（毫秒）
3. **用户标识**：记录当前登录用户ID（已登录请求）或标记为匿名
4. **分级日志**：正常请求 INFO 级别、慢请求 WARN 级别（超过阈值）、异常请求 ERROR 级别
5. **敏感信息脱敏**：对登录接口的密码等敏感字段进行脱敏处理
6. **TraceId 传递**：与全链路追踪组件协作，在日志中输出 traceId

## 为什么（Why）

1. **问题排查**：线上问题排查最基本的需求是"谁在什么时间访问了什么接口、返回了什么结果"，没有请求日志就如同盲人摸象
2. **性能监控**：通过记录每个接口的响应时间，可以发现慢接口、评估系统性能瓶颈
3. **安全审计**：记录谁访问了什么数据、做了什么操作，满足安全审计需求
4. **使用分析**：统计接口调用量、用户活跃度，为系统优化提供数据支撑
5. **异常定位**：当 GlobalExceptionHandler 捕获到异常时，可通过 traceId 关联到具体的请求日志

# 二、定位与上下文（Where & When）

## 在哪里（Where）

位于 `gentry-core` 模块的 `com.gentry.core.web` 包中，作为 Servlet Filter 注册在 Spring Boot Filter 链的最前端（最高优先级），确保所有请求（包括静态资源）都经过日志记录。

在请求处理链路中的位置：

```
HTTP Request
  → [TraceIdFilter]           ← 生成 traceId
  → [RequestLogFilter]        ← 记录请求信息，启动计时
  → [Sa-Token Filter]         ← 认证鉴权
  → DispatcherServlet
  → Controller → Service → Mapper
  → [RequestLogFilter]        ← 记录响应信息和耗时
  → HTTP Response
```

依赖关系：

- **被依赖方**：全平台所有 HTTP 接口的日志记录
- **依赖方**：
  - Servlet API（`javax.servlet.Filter`）
  - `ContentCachingRequestWrapper` / `ContentCachingResponseWrapper`（Spring 提供）
  - SLF4J / Logback（日志框架）
  - `UserContext`（获取当前用户ID）
  - MDC（Mapped Diagnostic Context，传递 traceId）

## 在何时（When）

触发场景：

| 触发场景 | 日志级别 | 说明 |
|----------|----------|------|
| 正常请求（耗时 < 500ms） | INFO | 记录请求和响应摘要 |
| 慢请求（耗时 >= 500ms） | WARN | 标记为慢请求，便于关注 |
| 异常请求（状态码 >= 500） | ERROR | 记录异常信息 |
| 静态资源请求 | 不记录 | 排除 `.js`、`.css`、`.png` 等静态资源 |
| 健康检查请求 | 不记录 | 排除 `/actuator/health` 等监控探针 |

# 四、实现思路（How）

## 核心技术方案

### 4.1 Filter 注册方式

通过 Spring Boot 的 `FilterRegistrationBean` 注册，确保执行顺序：

```java
@Bean
public FilterRegistrationBean<RequestLogFilter> requestLogFilterRegistration() {
    FilterRegistrationBean<RequestLogFilter> registration = new FilterRegistrationBean<>();
    registration.setFilter(new RequestLogFilter());
    registration.addUrlPatterns("/*");
    registration.setOrder(Ordered.HIGHEST_PRECEDENCE + 1); // TraceIdFilter 之后
    return registration;
}
```

### 4.2 请求/响应包装

使用 Spring 提供的 `ContentCachingRequestWrapper` 和 `ContentCachingResponseWrapper` 包装原始请求和响应，使请求体和响应体可被多次读取：

```java
@Override
public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
    ContentCachingRequestWrapper wrappedRequest = new ContentCachingRequestWrapper(
        (HttpServletRequest) request, maxBodyLength);
    ContentCachingResponseWrapper wrappedResponse = new ContentCachingResponseWrapper(
        (HttpServletResponse) response);

    long startTime = System.currentTimeMillis();
    try {
        chain.doFilter(wrappedRequest, wrappedResponse);
    } finally {
        long duration = System.currentTimeMillis() - startTime;
        logRequest(wrappedRequest, wrappedResponse, duration);
        wrappedResponse.copyBodyToResponse(); // 将缓存响应写回客户端
    }
}
```

### 4.3 日志格式

**INFO 级别（正常请求）：**

```
[traceId] GET /api/v1/vehicles?page=1&size=10 - userId:42 - 200 - 125ms
```

**WARN 级别（慢请求）：**

```
[traceId] SLOW REQUEST - GET /api/v1/vehicles?page=1&size=10 - userId:42 - 200 - 1523ms
```

**ERROR 级别（异常请求）：**

```
[traceId] ERROR REQUEST - POST /api/v1/vehicles - userId:42 - 500 - 2341ms
```

### 4.4 日志输出字段

| 字段 | 来源 | 说明 |
|------|------|------|
| traceId | MDC.get("traceId") | 全链路追踪ID |
| method | request.getMethod() | GET/POST/PUT/DELETE |
| path | request.getRequestURI() | 请求路径 |
| query | request.getQueryString() | 查询参数（脱敏后） |
| clientIP | X-Forwarded-For / remoteAddr | 客户端真实IP |
| userId | UserContext.getUserId() | 当前登录用户ID（匿名为 "-"） |
| status | response.getStatus() | HTTP 状态码 |
| duration | 计算值 | 请求耗时（毫秒） |
| body | wrappedRequest.getContentAsByteArray() | 请求体（可选，仅特定接口） |

### 4.5 敏感信息脱敏

对特定路径的请求体进行脱敏处理：

| 路径 | 脱敏字段 | 脱敏方式 |
|------|----------|----------|
| `/auth/login` | password | 替换为 `******` |
| `/auth/register` | password | 替换为 `******` |
| `/users/password` | oldPassword, newPassword | 替换为 `******` |
| 其他含 password 字段的请求体 | password | 替换为 `******` |

脱敏实现：使用正则表达式匹配 JSON 中的 `"password":"xxx"` 模式，替换为 `"password":"******"`。

### 4.6 排除规则

以下请求不记录日志，减少噪音：

| 排除项 | 匹配规则 | 原因 |
|--------|----------|------|
| 静态资源 | `*.js`, `*.css`, `*.png`, `*.jpg`, `*.ico`, `*.svg`, `*.woff2` | 无业务意义 |
| 健康检查 | `/actuator/health`, `/actuator/info` | 探针高频访问 |
| Swagger | `/swagger-ui/*`, `/v3/api-docs/*` | 开发工具 |
| favicon | `/favicon.ico` | 浏览器自动请求 |

### 4.7 请求体记录策略

| 内容类型 | 是否记录请求体 | 最大长度 | 说明 |
|----------|----------------|----------|------|
| application/json | 是 | 2048 字符 | 业务接口主要格式 |
| application/x-www-form-urlencoded | 是 | 2048 字符 | 表单提交 |
| multipart/form-data | 否 | - | 文件上传不记录 |
| 其他 | 否 | - | 二进制流等不记录 |

# 五、预期效果与验收标准

## 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 过滤器自身耗时 | < 2ms | 仅记录日志，不阻塞请求 |
| 请求体缓存开销 | < 1ms | 内存拷贝操作 |
| 日志写入 | 异步 | 通过 Logback AsyncAppender 异步写入 |
| 日志文件大小 | 100MB/天后轮转 | 按天滚动，保留 30 天 |

## 功能验收标准

| 编号 | 验收项 | 验证方式 |
|------|--------|----------|
| L-001 | 记录请求方法和路径 | 查看日志文件，确认包含 GET/POST 和完整路径 |
| L-002 | 记录客户端真实IP | 通过代理访问，确认记录的是 X-Forwarded-For |
| L-003 | 记录登录用户ID | 登录后访问接口，确认日志包含 userId |
| L-004 | 匿名请求标记为 "-" | 未登录访问公开接口，确认 userId 显示为 "-" |
| L-005 | 记录响应状态码 | 查看日志，确认包含 200/400/500 等状态码 |
| L-006 | 记录响应耗时 | 查看日志，确认包含毫秒级耗时 |
| L-007 | 慢请求标记为 WARN | 模拟慢接口，确认日志级别为 WARN |
| L-008 | 异常请求标记为 ERROR | 触发 500 错误，确认日志级别为 ERROR |
| L-009 | 登录密码脱敏 | 调用登录接口，确认日志中 password 显示为 ****** |
| L-010 | 静态资源不记录 | 访问 .js/.css 文件，确认无日志输出 |
| L-011 | 健康检查不记录 | 访问 /actuator/health，确认无日志输出 |
| L-012 | 日志包含 traceId | 查看日志，确认每条日志包含 traceId |
