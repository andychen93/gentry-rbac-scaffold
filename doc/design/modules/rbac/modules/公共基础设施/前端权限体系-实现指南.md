# 一、快速开始

## 1.1 添加新权限点（完整流程）

### Step 1：后端定义权限

打开菜单管理页面，新增菜单：

| 字段 | 值 | 说明 |
|------|-----|------|
| 菜单名称 | 删除订单 | 在侧栏显示的文案 |
| 菜单路径 | （留空） | 按钮类型菜单无路由 |
| 权限标识 | `business:order:delete` | **关键**：前后端对应，规范：`{module}:{entity}:{action}` |
| 菜单类型 | 按钮 | 选择「按钮」type=3 |
| 图标 | （留空） | 按钮无需图标 |
| 所属角色 | 选择角色 | 哪些角色有此权限 |
| 状态 | 启用 | 1=启用 / 0=禁用 |

此时后端插入：

```sql
INSERT INTO sys_menu (name, path, permission, type, status, create_time, ...)
VALUES ('删除订单', NULL, 'business:order:delete', 3, 1, NOW(), ...);

-- 然后在角色管理页面关联角色-菜单
INSERT INTO sys_role_menu (role_id, menu_id)
VALUES (?, (SELECT id FROM sys_menu WHERE permission = 'business:order:delete'));
```

### Step 2：前端使用权限

在表格操作列中使用 `RowActions`：

```typescript
import { RowActions } from '@gentry/kit';
import { DeleteOutlined, EditOutlined } from '@ant-design/icons';

function OrderTable() {
  return (
    <ProTable
      columns={[
        // ... 其他列
        {
          title: '操作',
          render: (_, record) => (
            <RowActions
              items={[
                {
                  key: 'edit',
                  label: '编辑',
                  icon: <EditOutlined />,
                  perm: 'business:order:edit',
                  onClick: () => handleEdit(record),
                },
                {
                  key: 'delete',
                  label: '删除',
                  icon: <DeleteOutlined />,
                  perm: 'business:order:delete',  // ← 权限标识
                  danger: true,
                  onClick: () => handleDelete(record),
                },
              ]}
            />
          ),
        },
      ]}
      // ...
    />
  );
}
```

或手写判断：

```typescript
function OrderDetailPage() {
  const hasDeletePerm = useUserStore(s => 
    s.hasPermission('business:order:delete')
  );

  return (
    <div>
      {hasDeletePerm && (
        <Button danger onClick={handleDelete}>
          删除订单
        </Button>
      )}
    </div>
  );
}
```

### Step 3：测试验证

1. **管理员账号测试**：
   - 账号：admin / 密码：Abc@123456
   - 进入对应页面，确认看到「删除」按钮

2. **普通账号测试**：
   - 创建新账号，分配普通角色（无 delete 权限）
   - 登录该账号，进入对应页面
   - 确认看不到「删除」按钮

3. **权限变更测试**：
   - 管理员为普通账号添加 delete 权限
   - 普通账号重新登录
   - 确认现在看到「删除」按钮

# 二、权限命名规范详解

## 2.1 格式规范

```
{module}:{entity}:{action}
```

### module（模块名）

| 模块 | 代码 | 权限前缀 |
|------|------|--------|
| 系统管理 | rbac | `system:` |
| 业务-订单 | order | `business:order:` |
| 业务-设备 | device | `business:device:` |
| 业务-车辆 | vehicle | `business:vehicle:` |
| 运维监控 | monitor | `monitor:` |

### entity（实体名）

| 实体 | 代码 |
|------|------|
| 用户 | user |
| 角色 | role |
| 菜单 | menu |
| 部门 | dept |
| 字典 | dict |
| 订单 | order |
| 设备 | device |
| 车辆 | vehicle |

### action（操作名）

| 操作 | 代码 | 含义 |
|------|------|------|
| 查看列表 | list | 访问列表页（菜单权限） |
| 查看详情 | view 或 detail | 查看详情页 |
| 新增 | add 或 create | 创建新记录 |
| 编辑 | edit 或 update | 修改记录 |
| 删除 | delete | 删除记录 |
| 导出 | export | 导出数据 |
| 导入 | import | 导入数据 |
| 审批 | approve | 审批流程 |
| 驳回 | reject | 驳回流程 |
| 发送 | send | 发送通知 |

## 2.2 完整示例

### 系统管理 - 用户管理

```
系统:用户:查看列表     system:user:list      (菜单权限，type=2)
系统:用户:查看详情     system:user:view      (按钮权限，type=3)
系统:用户:新增        system:user:add       (按钮权限，type=3)
系统:用户:编辑        system:user:edit      (按钮权限，type=3)
系统:用户:删除        system:user:delete    (按钮权限，type=3)
系统:用户:导出        system:user:export    (按钮权限，type=3)
```

### 业务 - 订单管理

```
业务:订单:查看列表     business:order:list      (菜单权限)
业务:订单:查看详情     business:order:view      (按钮权限)
业务:订单:新增        business:order:add       (按钮权限)
业务:订单:编辑        business:order:edit      (按钮权限)
业务:订单:删除        business:order:delete    (按钮权限)
业务:订单:导出        business:order:export    (按钮权限)
业务:订单:审批        business:order:approve   (按钮权限)
业务:订单:驳回        business:order:reject    (按钮权限)
```

# 三、权限渲染方式对比

## 3.1 RowActions（推荐，表格行操作）

### 特点

- 自动处理权限判断
- 自动隐藏无权限按钮
- 图标 + Tooltip 的紧凑设计
- 支持删除确认弹窗（danger 属性）

### 代码

```typescript
<RowActions
  items={[
    {
      key: 'edit',
      label: '编辑',
      icon: <EditOutlined />,
      perm: 'business:order:edit',
      onClick: () => handleEdit(record),
    },
    {
      key: 'delete',
      label: '删除',
      icon: <DeleteOutlined />,
      perm: 'business:order:delete',
      danger: true,
      onClick: () => handleDelete(record),
    },
  ]}
/>
```

### 适用场景

- ✅ 表格行操作
- ✅ 多个操作按钮并列
- ✅ 需要图标展示

---

## 3.2 手写权限判断（灵活，单个按钮）

### 特点

- 完全自由控制渲染
- 适合单个按钮或复杂逻辑
- 需要手动判断权限

### 代码

```typescript
const hasEditPerm = useUserStore(s => s.hasPermission('business:order:edit'));

if (hasEditPerm) {
  return <Button type="primary" onClick={handleEdit}>编辑</Button>;
}
```

### 适用场景

- ✅ 单个按钮或操作
- ✅ 需要自定义样式
- ✅ 按钮位置不固定

---

## 3.3 条件组件渲染（隐藏整块功能）

### 特点

- 隐藏整个功能模块或表单字段
- 适合页面级权限控制

### 代码

```typescript
const EditSection = () => {
  const hasEditPerm = useUserStore(s => s.hasPermission('business:order:edit'));
  
  if (!hasEditPerm) return null;
  
  return (
    <Form.Item label="订单状态">
      <Select options={[...]} />
    </Form.Item>
  );
};

export default function OrderDetail() {
  return (
    <Form>
      <EditSection />
      {/* 其他字段 */}
    </Form>
  );
}
```

### 适用场景

- ✅ 整个表单字段或表单部分
- ✅ 整个功能模块
- ✅ 高级功能（付费功能）

```typescript
      onClick={() => { /* 打开对话框 */ }}

      新增订单
    </Button>
```

## 4.3 复杂权限逻辑

```typescript
// 场景：仅 admin 和 manager 能删除，且记录状态是"草稿"才能删除

function CanDeleteOrder(record: Order) {
  const hasDeletePerm = useUserStore(s => 
    s.hasPermission('business:order:delete')
  );
  
  // 权限不足
  if (!hasDeletePerm) return false;
  
  // 记录状态不是"草稿"
  if (record.status !== 'draft') return false;
  
  return true;
}

// 在 RowActions 中使用
<RowActions
  items={[
    {
      key: 'delete',
      label: '删除',
      icon: <DeleteOutlined />,
      perm: 'business:order:delete',
      disabled: !CanDeleteOrder(record),  // 灰显按钮
      onClick: () => handleDelete(record),
    },
  ]}
/>
```

## 4.4 菜单权限隐藏整个模块

```typescript
// 菜单权限由后端控制返回
// 前端 userStore.menus 已包含过滤后的菜单列表
// AppSidebar 自动渲染，无需前端额外处理

// 如果想手动隐藏整个模块（高级用法）：
function BusinessModule() {
  const hasPermission = useUserStore(s => s.hasPermission('business:order:list'));
  
  if (!hasPermission) {
    return <AccessDenied />;  // 显示无权限提示
  }
  
  return <OrderPage />;
}
```

# 五、权限测试清单

创建新权限点后，按此清单验证：

## 5.1 权限定义检查

- [ ] 权限标识已在菜单管理中创建
- [ ] 权限标识遵循命名规范（`{module}:{entity}:{action}`）
- [ ] 权限已关联到至少一个角色
- [ ] 权限类型正确（菜单权限 type=2，按钮权限 type=3）

## 5.2 前端代码检查

- [ ] 前端代码中的权限字符串与后端完全一致（区分大小写）
- [ ] 使用了正确的渲染方式（RowActions / hasPermission / 条件渲染）
- [ ] 权限判断的变量命名清晰（如 `hasDeletePerm`）
- [ ] 所有路径都考虑了无权限的情况

## 5.3 功能验证

- [ ] 有权限的账号能看到功能（菜单/按钮/页面）
- [ ] 无权限的账号看不到功能
- [ ] 超级管理员 (super_admin) 能看到所有功能
- [ ] 权限变更后重新登录立即生效

## 5.4 边界情况

- [ ] 页面刷新后权限不丢失
- [ ] 登出再登入，权限正确还原
- [ ] 多个权限点组合时，逻辑正确（如既要 edit 又要 approve）

## 5.5 后端校验（安全）

- [ ] 调用 API 时后端返回 `@SaCheckPermission` 校验错误（403）
- [ ] 无权限调用仍然返回 30003 错误
- [ ] 错误信息提示用户权限不足

```json
  "code": 30003,
  "message": "权限不足",
  "traceId": "..."
}
```

这是正常的，说明后端权限校验正在工作。

# 七、常见错误与解决

| 问题 | 原因 | 解决 |
|------|------|------|
| 权限判断始终为 false | userInfo 还没加载 | 检查是否在登录完成前使用权限，添加 `isLoggedIn` 判断 |
| 页面刷新后按钮消失 | userInfo 丢失，但后续恢复 | 属于正常逻辑，App.tsx 会自动恢复 |
| 权限字符串不匹配 | 前后端拼写不一致 | 检查大小写和下划线 |
| 超级管理员看不到权限 | 未配置 super_admin 角色 | 确保系统中有 role_code='super_admin' 的角色 |
| 按钮没有隐藏 | 没有使用 perm 属性 | RowActions 需要 perm 属性才会判断权限 |
| 权限变更后没生效 | 在线用户需要重新登录 | 提示用户重新登录或提供「刷新权限」功能 |

# 十、权限最佳实践总结

## 做

- ✅ 用 `hasPermission()` 判断权限
- ✅ 用 RowActions 渲染表格操作
- ✅ 权限标识遵循命名规范
- ✅ 前后端权限标识一致
- ✅ 后端 @SaCheckPermission 校验
- ✅ 提供用户友好的无权限提示

## 不要

- ❌ 硬编码权限检查逻辑
- ❌ 在多个地方维护权限列表
- ❌ 只靠前端隐藏按钮（后端必须校验）
- ❌ 权限命名随意（必须规范）
- ❌ 权限变更后忽略在线用户（提示重新登录）
