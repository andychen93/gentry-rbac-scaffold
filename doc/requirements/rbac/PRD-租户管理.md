## 一、功能概述

### 1.1 功能定位

租户管理是**多租户 SaaS 平台的核心基础设施**，负责管理平台上的企业客户。每个租户拥有独立的数据空间，实现数据隔离。

### 1.2 业务场景

| 场景 | 描述 | 操作角色 |
|------|------|---------|
| 平台运营 | 平台管理员创建新企业客户账号 | 超级管理员 |
| 企业入驻 | 新企业注册开通服务 | 超级管理员 |
| 租户管理 | 修改企业信息、配置参数 | 超级管理员 |
| 租户禁用 | 企业欠费或违规时暂停服务 | 超级管理员 |

### 1.3 用户故事

```
作为一名【平台运营人员】
我想要【创建和管理租户】
以便于【为不同企业客户提供独立的车辆管理服务】

验收标准：
- 可创建新租户并配置基本信息
- 可修改租户信息
- 可禁用/启用租户
- 可配置租户级参数（设备限额、功能开关等）
```

### 2.2 租户列表查询（T-001）

#### 功能描述

以分页列表形式展示所有租户，支持多条件筛选和排序。

| 创建时间范围 | date | 否 | 开始日期-结束日期 |

#### 列表字段

| 字段 | 显示名称 | 宽度 | 是否排序 | 说明 |
|------|---------|------|---------|------|

| user_count | 用户数量 | 100px | 否 | 关联用户数 |
| expire_time | 到期时间 | 150px | 是 | - |
| status | 状态 | 80px | 否 | Tag 展示 |
| create_time | 创建时间 | 150px | 是 | - |
| operation | 操作 | 150px | - | 操作按钮 |

#### 操作按钮

| 按钮 | 显示条件 | 点击行为 |
|------|---------|---------|

### 2.3 新增租户（T-002）

#### 功能描述

创建新租户，系统自动创建默认管理员账号和默认部门。

#### 新增表单字段

| 字段 | 显示名称 | 类型 | 必填 | 校验规则 | 说明 |
|------|---------|------|------|---------|------|
| code | 租户编码 | Input | 是 | 字母数字，6-20位，唯一 | 唯一标识 |
| tenantName | 租户名称 | Input | 是 | 2-50字符 | 企业全称 |
| contact | 联系人 | Input | 是 | 2-20字符 | - |
| phone | 联系电话 | Input | 是 | 11位手机号 | - |
| email | 联系邮箱 | Input | 否 | 邮箱格式 | - |
| expireTime | 到期时间 | DatePicker | 否 | - | 空则永不过期 |
| remark | 备注 | TextArea | 否 | 最多200字符 | - |

#### 创建时自动执行

| 序号 | 自动操作 | 说明 |
|------|---------|------|
| 1 | 创建默认部门 | 部门名称："{租户名称}"，作为根部门 |
| 2 | 创建管理员角色 | 角色编码：`ADMIN`，角色名称：管理员 |
| 3 | 创建管理员账号 | 用户名：`admin`，密码：随机生成并显示 |
| 4 | 分配角色 | 将管理员角色分配给 admin 用户 |
| 5 | 分配权限 | 管理员角色分配所有菜单权限 |

#### 接口设计

```
POST /api/v1/tenants
```

**请求参数：**

```json
{
  "code": "TENANT002",
  "tenantName": "京东物流股份有限公司",
  "contact": "李四",
  "phone": "13900139000",
  "email": "lisi@jd.com",
  "expireTime": "2027-03-30T00:00:00",
  "remark": "京东物流车队管理系统"
}
```

**响应示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "tenantId": 2,
    "code": "TENANT002",
    "adminUsername": "admin",
    "adminPassword": "Abc@123456",
    "message": "租户创建成功，请妥善保管管理员密码"
  }
}
```

#### 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-001 | 租户编码全局唯一，创建后不可修改 |
| BR-002 | 租户名称租户内唯一 |
| BR-003 | 管理员密码仅创建时显示一次，需提示用户保存 |
| BR-004 | 联系电话格式校验：1开头的11位数字 |

### 2.7 禁用/启用租户（T-006）

#### 功能描述

切换租户的启用/禁用状态。

#### 业务规则

| 规则编号 | 规则描述 |
|---------|---------|
| BR-001 | 禁用租户后，该租户下所有用户无法登录 |
| BR-002 | 禁用租户不影响已登录用户的当前操作，但下次登录将被拒绝 |
| BR-003 | 禁用操作需要二次确认 |
| BR-004 | 启用租户后，所有用户恢复正常登录 |

#### 接口设计

```
PUT /api/v1/tenants/{id}/status
```

**请求参数：**

```json
{
  "status": 0
}
```

## 三、数据模型

### 3.1 租户表（sys_tenant）

| 字段名 | 类型 | 可空 | 默认值 | 说明 |
|--------|------|------|--------|------|
| id | BIGINT | NO | - | 主键（雪花算法） |
| tenant_code | VARCHAR(50) | NO | - | 租户编码（唯一） |
| tenant_name | VARCHAR(100) | NO | - | 租户名称 |
| contact | VARCHAR(50) | NO | - | 联系人 |
| phone | VARCHAR(20) | NO | - | 联系电话 |
| email | VARCHAR(100) | YES | NULL | 联系邮箱 |
| status | SMALLINT | NO | 1 | 状态：0=禁用，1=启用 |
| expire_time | TIMESTAMP | YES | NULL | 过期时间 |
| config | JSON | YES | NULL | 租户配置 |
| remark | VARCHAR(500) | YES | NULL | 备注 |
| create_time | TIMESTAMP | NO | CURRENT_TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | NO | CURRENT_TIMESTAMP | 更新时间 |
| deleted | SMALLINT | NO | 0 | 逻辑删除：0=正常，1=删除 |

### 3.2 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| pk_sys_tenant | id | PRIMARY | 主键索引 |
| uk_tenant_code | tenant_code | UNIQUE | 租户编码唯一索引 |
| idx_tenant_status | status | NORMAL | 状态索引 |
